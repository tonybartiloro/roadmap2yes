## What I verified (no finding)
- Security: every action validates with zod first, then takes the session from cookies via `createClient()` (anon key plus the user's JWT). No service key and no `server-only` leak: `server.ts` imports `server-only`; `data.ts` has no Next import and no secrets. `wedding_id` is never taken from the client: `addOption` and `setReaction` read it from a row that RLS already made visible, so a foreign decision/option id returns nothing and maps to `forbidden` (no IDOR). `user_id` for reactions comes from the verified claims, not from the input. Error messages go through `mapDbError`: allowlisted codes only, otherwise the generic text; no SQL or constraint names reach the client. External links are limited to `http(s)` by zod and a DB check, rendered with `rel="noopener noreferrer"`. `locationOnly` is client-chosen, but the DB trigger freezes dates on a taken decision, so it cannot be abused.
- Correctness: choose and reopen use the RPCs (atomic, expected version). Period choice requires the exact day, validated in the sheet and by the RPC, tested including out-of-period (AC64, D33). Reopen reason is mandatory in the UI, the RPC and the tests. Discarded options sit in a collapsed `<details>` with a count. "Confronta 2" is capped at 2 and keyboard-operable. Reactions are non-binding and shown to the partner with icon plus text. Reference flow (confirm sheet with consequence count, Annulla toast of 10 s, "Torna automatico") matches §3.8. Linked location is shown in the list and compare (AC60 test at `decisions.data.test.ts:105`).
- Accessibility: sheets are the shared Radix `Sheet` (focus trap and return), pending state blocks dismissal, fields have `label`/`aria-invalid`/`aria-describedby`, error `role="alert"`, buttons are `h-11`, icons are `aria-hidden` with text beside them, checkbox label contains the option title.
- Next 16: `params` awaited, `notFound()`, segment `error.tsx` with hand-off of service outages to the root boundary, `loading.tsx`, client/server split correct.
