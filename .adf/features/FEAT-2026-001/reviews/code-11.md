Declared deviations (my evaluation):
1. **`record_seen` once per session (30 min).** Accepted. AC41 asks for the partner's recent changes since the last access; `record_seen` moves `last_seen_at` into `previous_seen_at` on every call, so calling it on each render would make a reload erase the news. The gate matches the plan's intent. It is robust under concurrency. For two overlapping requests that both read the same `before`, `reconcileVisit` takes the stored `last_seen_at` when the DB's `previous_seen_at` is not it, and I traced the order R1/R2 and R2/R1. When a request reads after the other has written, it is inside the 30 minutes and skips. The first visit (null) stays null. A non-infra `record_seen` error degrades to the stored state, and an outage is rethrown. The known limit (partner changes made during your last session show once more) is acceptable: the window starts at the beginning of the previous session. The real clock against the DB clock has a negligible skew. See REV-3 for the test.
2. **WelcomeCard only for slot B, first visit, not dismissed.** Accepted. It matches plan §9 and DES-20. Slot A's first visit shows nothing, which is also right: there are no news. A reload before dismissal keeps the card (the state is not advanced).
3. **localStorage fallback.** Accepted (REV-5 for the missing message). The hook is SSR-safe (`useSyncExternalStore`) and never throws.
4. **User-client reads of the three event sources.** Accepted: RLS is the only authorization and the policies need wedding membership. See REV-2 for the limit.
5. **No `loading.tsx` / `error.tsx`.** `error.tsx` accepted (the root boundary exists and outages are rethrown). `loading.tsx` is REV-1.
6. **Links to unbuilt pages.** Accepted for now (REV-5).
