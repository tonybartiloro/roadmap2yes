## What I verified (no finding)
- RLS and grants follow §3.1: no INSERT policy on `decisions`; `status`, `chosen_*`, `due_overridden`, `needs_review`, `completed_*`, `template_*`, `source` have no column grant; `decision_events` select only; `weddings.manual_reference_option_id` has no grant.
- Composite FKs: `decision_options`, `date_scenarios.option_id`, `location_option_id`, `decision_events`, `option_reactions` and `weddings.manual_reference_option_id` all carry `wedding_id`; tests cover a foreign decision (23503) and a foreign location.
- Every SECURITY DEFINER sets `search_path = pg_catalog, pg_temp`; allowlist revokes from public/anon/authenticated first; private helpers are not granted. `r2y.internal` cannot be set through the API.
- `decision_events` is append-only for all (update, delete, truncate triggers; tested including the owner and the service key).
- `choose_option` and `reopen_decision` are atomic (one transaction, event last, version check, exact day inside the period, original period kept in the event payload).
- Reference rule matches `reference.ts`: chosen, then manual (open and not deleted, even if past), then earliest not-past (period by first day), else earliest; tie-break on id as text. The order by `(date_from < today)` is the same as `upcoming` first.
- Recalculation touches only template tasks with an offset that are `todo`, not overridden, not deleted (AC28, tested for each exclusion). `due_overridden` uses `current_user = 'authenticated'`: correct for PostgREST and for the DEFINER sync.
- `insert_template_tasks` is idempotent via the unique index with deleted rows included; a deleted task is skipped (AC31).
- `add_date_offset`: 65 vectors pass; months first with clamp, then weeks/days.
