## Round 2: the proxy-served neutral 404, checked
- **Identical for every cause.** `neutralResponse()` is one constant body (`neutral-html.ts`, no interpolated data), status 404, same `Content-Type` and `X-Robots-Tag`; `decorate` adds `private, no-store` and the referrer policy. Malformed token, broken escape, unknown, revoked, expired and no-recipient all go through it; test "byte-identical" covers the two paths. The only per-request variance is the signed-in member's refreshed cookies, independent of the cause. No name, date, theme, link or script.
- **One BR9 failure per dead open.** `rsvp_gate` writes nothing; the proxy then calls `rsvp_page` once (it hits the IP key) and returns the 404, so the page never runs. A locked IP gets the 429 before this. Malformed tokens do no DB call (QA-15) and count nothing. Only residual: REV-122(c).
- **No extra call for a working link.** The second call happens only when `gate !== null && gate.themeId === null`; the gate returns the wedding's `theme_id` for a working link and `weddings.theme_id` is `NOT NULL` (`core.sql:116`); a failed gate, a blocked IP and a POST never reach it (tests).
- **Fail-open.** `rsvpLoadPage` with `timeoutMs` aborts at 3 s and returns `retry`; `ok`, `retry`, timeout and a failed gate let the request through to the page, which decides (and counts).
- **Logs/cache.** No logging; token/hash only travel in the RPC body inside the wrapper; `Cache-Control: private, no-store` on the 404. The page no longer uses `notFound()`/`not-found.tsx`, so no cause-dependent markup remains. `LinkUnavailable` is a client component that imports only text constants (no secret, no Node code).

## Round 3: `same-origin` for the page (DES-37), checked, no new finding
- **Only where intended.** `referrerPolicyFor` gives `same-origin` to `/rsvp` and `/rsvp/*` through `decorate` with the default (page GET, server-action POST, guard redirect/rewrite/deny on `/rsvp`); the proxy-written neutral 404 (malformed and dead-link branches) and the 429 pass an explicit `"no-referrer"`, so all neutral causes still have identical status, body and headers. `/invito`, `/auth`, `/email` unchanged.
- **Meta/header consistent.** `RsvpShell` renders `<meta name="referrer" content="same-origin">`, matching the header on every response that renders the shell (200 page, fail-open neutral 200, no-JS POST result); `neutral-html.ts` keeps the `no-referrer` meta and header. The header is authoritative.
- **No third party gets a Referer.** `same-origin` sends nothing cross-origin; no `http(s)://` literal in the T7 files, no external link, image or font, CSP `default-src 'self'`.
- **Origin check intact.** No `serverActions`/`allowedOrigins` option in `next.config.ts` or `src`; the fix makes the browser send the real `Origin`, so Next's same-host check still decides. Tests cover the page, the POST and the neutral paths (the dead-link neutral branch is covered by code reading and the shared constant; the test exercises the malformed branch).
- Layout changes (DES-38/39/43/40: chevron, card markup) have no security surface (no new data, link or resource).
