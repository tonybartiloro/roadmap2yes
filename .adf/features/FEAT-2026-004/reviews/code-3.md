## Checked, no finding
- **429 text vs `Retry-After`** (point asked): the HTML says "riprova tra 15 minuti" (static), `Retry-After` is the dynamic remainder (clamped to at least 1, at most 900 because the lock is 15 min). That is the literal wording of AC10 and `design.md` §D/§wording, and it is never shorter than the truth for the reader. The page adds one line ("controlla di averlo copiato per intero"); harmless, not an oracle.
- **Gate ordering**: guards first, gate only when `decision.action === "next"` and `backend === "ok"`; an outage never calls the DB for the gate; the gate is bounded (3 s) and fail-open; malformed tokens never reach the DB (QA-15). Percent-encoded token variants (`%41…`) skip the gate (the shape test runs on the encoded path) and reach the page, which counts them: only the 429-vs-404 and the theme differ, no security effect.
- **Theme header**: proxy always deletes the client's `x-r2y-theme`; sets it only from an approved id returned by the gate for a working link; `getActiveThemeId` gives it precedence and re-validates with `isApprovedThemeId`; tests cover forged header on `/percorso`, `/servizio`, and an unknown RSVP link. A signed-in partner opening a dead link still sees their own theme via the normal DB lookup (not a leak to third parties).
- **`resolveNow` (QA-1)**: the proxy uses `resolveNow({cookieValue})` (ignored without `E2E_CLOCK=1` or with `VERCEL`, tested); the actions use `getNow()`; `loadRsvp`/`view.ts` take `now` as a parameter; no `new Date()`/`Date.now()` in `src/features/rsvp`.
- **`rsvp_links`**: every read lists columns (`id, revoked_at`; export `id, group_id, guest_id, created_at, revoked_at, shared_at`); no `select('*')`; `token_hash` is only ever written (RPC) or compared by `rsvp_link_matches`, which is DEFINER, wedding-scoped, and returns `link_not_found` for a foreign link (no oracle); pgTAP and the allowlists were updated (`core_schema`, `qa_catalog_matrix`, `matrix.ts`).
- **Actions**: zod `.strict()` on every input, session from cookies, secret read at call time with one fixed message, `forbidden`/`link_*` mapped from SQLSTATE or exact business code only, no DB text returned, nothing logged, `revalidatePath` only on success. Permission is enforced by the RPCs (`guests/write`) and RLS, not by the action.
- **`view.ts`**: precedence Scaduto → Condiviso/Da condividere → Da rimandare → Nessun link as in the plan; expiry compares Europe/Rome day with `expires_on` (last working day, same as SQL); summaries "2 sì · 1 in attesa", WhatsApp text and `wa.me` encoding match `design.md` §1.2; "Crea link per tutti" count (recipients with no non-revoked link) equals "no working link" in every reachable case.
- **Export**: JSON gains `rsvpResponses`/`rsvpLinks` only, no token or hash (tested: no `token`, no 64-hex), CSV unchanged, `not_migrated` gives empty lists, any other failure is a fixed error without cause.
- **Degraded schema**: `loadRsvp` → `null` on `PGRST202/PGRST205/42P01/42883` (tested); `undo_guest_import` without `skipped` → 0 (tested); `loadGuests` fallback present (untested, REV-12).
- **Reported deviations accepted**: fake-secret refusal only on `VERCEL_ENV=production` (CI/e2e run `next start` with it; note that a self-hosted production without `VERCEL_ENV` would accept the fake value, fine for this deployment); `as string` on `p_ip_key` (tested: key present and `null`); `tests/lint-fixtures/guards.test.ts`; optional `GroupView.rsvpMode`; WhatsApp helper takes `couple` names as input (T8 supplies them); `rsvp_link_matches` + pgTAP edits.
