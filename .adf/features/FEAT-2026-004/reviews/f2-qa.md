# FEAT-2026-004 — F2 QA challenge of the test plan

Verdict: **needs changes** (4 blocking, 9 should, 4 note). Every AC1-AC14 has at least one test in the plan; the gaps are in how it can be proven (clock, shared limiter state, matrix, logs), not in coverage of AC numbers.

## AC coverage check
All of AC1-AC14 map to a level (pgTAP / unit / integration / acceptance / e2e). Weak spots: AC6 "si invia" (HTTP code on submit), AC10 "non modifica dati" (no definition), AC12 (contradicted by Q-P1), AC14 "Novità, log" (no test), AC11 "doppio invio" (only e2e, no DB-level concurrency).

## Blocking

**QA-1 — Clock not plumbed to the public page and couple list (AC12, BR7, AC8 "Scaduto").** Evidence: plan "Regole in SQL" gives `p_now` to RPCs "per gli e2e" but "Server (Next.js)" never says proxy `gate`, `page`, `submitRsvp` and `loadRsvp`/`rsvp_status` take `now` from `resolveNow()` (`src/lib/clock.ts:9-17`, cookie `r2y-test-now` only with `E2E_CLOCK=1` and no `VERCEL`). Without it the e2e "scadenza con orologio" (T11) cannot be written, and `p_now` accepted from the client would be a bypass. Proposal: add to T5/T6/T7 "now = resolveNow(); passed as `p_now` to every RSVP RPC, never from request params"; unit test on `public-rpc.ts` (cookie ignored without `E2E_CLOCK`/with `VERCEL`); acceptance case: cookie sent to a server started without `E2E_CLOCK` still gives the live page. Expiry specs must be named `e2e/rsvp.time.spec.ts` (the `time` project is serial, `playwright.config.ts:10,90`); T11 owned files list `rsvp.public.spec.ts`/`rsvp.invitati.spec.ts` only: add `e2e/rsvp.time.spec.ts`.

**QA-2 — Shared IP limiter state will break the suite (BR9, AC10).** Evidence: 10 failures per IP per 15 min (plan `rsvp_page`, `limiter.ts`); all e2e/acceptance traffic comes from 127.0.0.1, and every neutral-page case (5 causes, malformed excluded) counts as a failure. After the 10th, later neutral tests get 429 instead of 404 and become order-dependent/flaky. `clientIp` takes `x-vercel-forwarded-for`/`x-forwarded-for` (`limiter-keys.ts:39-44`) and returns null when absent: plan does not say what the IP key does then. Proposal: (a) plan states null IP = no IP limit (or fixed rule) and pgTAP covers it; (b) every test uses a unique synthetic IP via `x-forwarded-for` (acceptance fetch headers, e2e `extraHTTPHeaders` per test) and has a helper to clear `private.rsvp_attempts` in `beforeEach`; (c) the 429 test uses its own IP and checks the 10th failure is 404, 11th is 429, valid token from that IP still 200, `Retry-After` > 0 and ≤ 900, unblock after 15 min via direct row shift (pattern of `login-neutral.test.ts:47`). Note: on Vercel the header is overwritten, locally it is spoofable: say so in `sicurezza.md`.

**QA-3 — Link lifecycle matrix is listed, not closed (AC9, BR1-BR5).** Evidence: Test plan row "Regole e RPC pubbliche" lists causes but no expected-value table; BR3 "Da rimandare" is the most error-prone rule. Proposal: a table-driven pgTAP (pattern `qa_catalog_matrix.test.sql`) in `rsvp_public.test.sql` with, per row, the action and expected (working?, recipient, `resend_guest_ids`, public page ok/neutral): group together/separate × link on group/person × {move in, move out, mode flip both ways, soft delete group, restore group, soft delete person, restore person, purge person, purge group, import then undo, revoke, rotate, expiry, date reopened}. Also: empty group (all members deleted) → neutral; person in two successive groups with links covered by exactly one link; revoke then new link not shared → "Da condividere" not "Da rimandare"; rotate → old revoked, new working, responses kept; dormant link reactivates (BR4) both for group and personal; wedding A token never returns wedding B (same names, same decision keys). Unit `view.ts` mirrors the precedence with one case per row of the four-step precedence including Scaduto beating all.

**QA-4 — Neutral-response identity test is under-specified (AC6).** Evidence: T10 "404 neutro identico (corpo e stato)". Next streams RSC payloads with nonces/build ids, so raw bodies differ; and `submit` neutral is a 200 in a server action (plan "Alternatives", Q-P2) while the GET is 404. Proposal: compare status, normalized HTML (strip nonces/ids) and relevant headers (`Cache-Control`, `X-Robots-Tag`, `Referrer-Policy`, `Content-Type`) across the 5 causes (malformed, unknown, revoked, expired, no recipient) and across both themes (wedding theme must not leak: check absence of the wedding theme id in the neutral HTML, including `data-theme` and `x-r2y-theme` not echoed in the response). Add POST case: submit on revoked/expired/unknown token returns the same neutral content. See question QA-Q2.

## Should

**QA-5 — Expiry boundary (BR7, AC12).** Evidence: "fine del giorno +30, Europe/Rome". Add pgTAP at date+30 23:59:59 (working) and +31 00:00:00 (neutral) in Rome time, with a date whose +30 crosses DST (e.g. 2027-03-10 and 2027-10-05); reopened decision → no expiry; date change (`choose_option` again) revives links; `date_scenarios` with a range: state which date is used (`date_from`? last day?). Unit for the date helper if any in TS.

**QA-6 — Config/ownership gaps for tests.** `playwright.config.ts`, `vitest.config.ts` (env `RSVP_LINK_SECRET` fake, 32+ chars) and the acceptance server (needs `next start` or `HEADERS_BASE_URL`, see `headers.test.ts:12,25`) appear in no task. e2e seed (`e2e/support/seed.ts`) must derive tokens via `deriveRsvpToken` from `src/features/rsvp/token.ts` (dependency on T4) and create links via `rsvp_create_links`. Proposal: add `playwright.config.ts`/`vitest.config.ts` env to T4 (developer) or T11 (QA), and state T10/T11 import only `token.ts`. Seed 05 (T3) is separate from e2e seed: no overlap, but say that e2e never relies on the seed token.

**QA-7 — "Nessun token nei log" cannot be proven by an HTTP acceptance test (AC14, BR9).** Evidence: T10 "spia `console`": the Next server is another process. Proposal: integration test (T6/T7 owner dev, QA can write it in `tests/integration/rsvp.logs.test.ts`) calling `public-rpc.ts`/`submitRsvp` with a failing RPC whose Postgres error contains token hash and note text, spying `console.*` and asserting no token, hash, `diet_note`, status or ids; plus in e2e a capture of the webServer stdout (Playwright `webServer.stdout: 'pipe'`) grepped for the test token after the run. Also assert error codes returned to the browser never include Postgres messages.

**QA-8 — Public RPC input validation not listed (AC4, AC11, BR11).** Add pgTAP/integration cases for `rsvp_submit`: answers > 100 (100 ok, 101 rejected), `rsvp_create_links` > 1000, empty array, non-array JSON, duplicate ids (last wins), invalid status, diet value outside the four, duplicate diet values, `diet_note` 200 vs 201 chars, whitespace-only note, diet with status `no` (cleared), note with `<script>`, emoji and NUL character. The plan must say what a valid link with a malformed payload returns (error code distinct from neutral, never a 500). e2e: stored `<script>` note renders as text in the couple's sheet.

**QA-9 — No DB-level concurrency test (AC11).** Pattern exists in `tests/acceptance/concurrency.test.ts`. Add: N parallel `rsvp_submit` for the same person with different values (single row, last wins, no unique violation surfaced), identical resubmit leaves `answered_at`, `version` and the `audit_log` row count unchanged (AC11 "nessun effetto doppio"), and 21st submit on a link blocked under parallel load without exceeding 20 writes.

**QA-10 — "Novità" and analytics not tested (AC14).** Impacts says responses stay out of "Novità" (`src/features/home/data.ts:356` whitelist) but no test. Add a `home.data` integration case: responses and links created, "Novità" empty of them; and a pgTAP/unit that the whitelist does not contain `rsvp_*`. Note `tests/integration/home.data.test.ts` is not in any task's owned files: assign to QA.

**QA-11 — AC10 "aprire il link non modifica dati" lacks a definition.** `rsvp_page` writes `rsvp_attempts` on failure (BR9), so a naive "no writes" check fails. Define: snapshot of `rsvp_responses`, `rsvp_links`, `guests`, `audit_log` row counts and `max(updated_at)` before/after GET (valid and invalid token); only `private.rsvp_attempts` may change. `rsvp_gate` marked STABLE and tested to write nothing.

**QA-12 — Couple-side share/copy edge cases (AC1, D11).** Add e2e/integration: Condividi cancelled by the user (`AbortError`) does not register "Condiviso il"; clipboard denied shows an error and does not register; stale URL after rotation is replaced when the sheet reopens; "Annulla" restores the previous `shared_at` and the snapshot (`rsvp_unmark_shared`). Copy is verified in Chromium with `clipboard-read/write` permissions; in WebKit only assert no error (clipboard permissions are not reliable there) and keep the real-device check at Gate C.

**QA-13 — e2e is wider than the risk needs; run the heavy parts lower.** The couple-side e2e repeats lifecycle variants that QA-3 proves in pgTAP. Keep in e2e only: move → "Da rimandare", delete/restore, revoke/rotate → neutral, purge, read-only user, crea tutti. axe: 4 states (form, riepilogo, neutra, 429) x light/dark on the default theme plus one other theme; the 12-theme matrix only if `themes.spec.ts` does not already cover tokens contrast (check before writing). No-JS: one spec with `javaScriptEnabled: false` (submit, zero-choice line, Modifica). WebKit smoke stays 2 tests. Local run: `E2E_PORT=3300 npm run e2e` (project memory), WebKit only in CI unless `npm run e2e:install` was done; the `time` project is serial and slower: run it once on the integrated result.
