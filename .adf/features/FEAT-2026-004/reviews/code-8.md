## What was checked and found sound
- **URL lifecycle.** The URL is never in props of any page or server component: `GuestsScreen`/`LinkSheet` get only link ids, state and `canWrite`. It is fetched by `getLinkUrlAction` in an effect only when `showActions` (`canWrite` and a working link), so read-only users never call it (test `components.test.tsx:217-222`) and the server refuses them anyway (`rsvp_link_matches` checks `guests/write`, wedding scope and hash). It lives in component state only: no `localStorage`, `sessionStorage`, `useFormDraft`, console, toast, `role="alert"` or aria-live text. Every `toast` and `error` string is a fixed Italian text; failures in `copy`/`share` are swallowed into fixed messages and never include the error object.
- **Authorization.** Hidden buttons are UX only. Every write path (`createLinksAction`, `rotateLinkAction`, `revokeLinkAction`, `markSharedAction`, `unmarkSharedAction`, `setGroupModeAction`) re-checks session, zod `.strict()` shape and then RPCs that test `guests/write` on the caller's wedding. `unmarkSharedAction`'s client-held `previous` is not trusted for attribution (`shared_by` becomes the caller; future `shared_at` and foreign guests are ignored by SQL). The page's `canWriteGuests` fails closed (`false` on any error).
- **Bundle boundary.** `RSVP_LINK_SECRET` is read only in `actions.ts` through `lib/app-config` (server actions file; the client bundle gets reference ids). `data.ts` and `token.ts` are imported only by `actions.ts`, the server pages, the proxy and tests. `view.ts` imports `guests/data` as types only; `GuestSheet` imports `DIET_OPTIONS` from `rsvp/public/state.ts`, which has a type-only import of the server-only `public-rpc`. No client component imports `app-config`. The variable has no `NEXT_PUBLIC_` prefix. `token.ts` has no `server-only` marker by design (e2e seed); it takes the secret as an argument.
- **Diet data.** Shown only to members that reach this page (`guests/read`), only for "yes". No `diet` in any toast, aria-live or log in the diff. Read-only users also see presence and diet (consistent with the RLS select).
- **Link ids sent to read-only users** are uuids and not secrets: the token is HMAC(secret, id) (ADR-0003).
- **Clipboard / Web Share.** Refused clipboard: the URL goes to a selectable field, nothing is marked, nothing is sent anywhere. `AbortError` is silent, other share errors give a fixed text.
