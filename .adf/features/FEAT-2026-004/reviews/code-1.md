## Risposte (author, T1/T2)
- REV-1: fixed. `rsvp_hit` now takes the lock in the first statement (`insert ... on conflict (key_hash) do update ... returning`), so the cleanup (`skip locked`) can never delete the row in between. No race test: it needs two sessions (T10 concurrency covers the parallel part).
- REV-2: accepted as decided. No DB change; the plan row is amended by the coordinator; T5 maps any non-`invalid_answers` error on submit to the generic retry state, T10 adds the `\u0000` PostgREST case.
- REV-3: kept (DB rejects a blank note); T7's server action normalises blank to null (Q1).
- REV-4: pgTAP added (`rsvp_public`): the untouched string with microseconds round-trips to `[]`, a millisecond-truncated one reports the change. T7 must pass `answered_at` back as the untouched string (plan note for the coordinator).
- REV-5: rejected, no change. Positional order mirrors `rsvp_gate`/`rsvp_page`; Postgres cannot give a default to a parameter that precedes a non-default one, and reordering churns every caller for a typing nit. T5 passes `p_ip_key: null` explicitly (unit test on the null path).
- REV-6: accepted as a residual (trivial volume, pseudonymous); goes in `sicurezza.md`. Not added to the success path: it would add a delete to every page open.
- REV-7: fixed (see REV-103): `rsvp_unmark_shared` ignores `shared_by` from the client (it becomes the caller, null if nothing was shared) and refuses a future `shared_at`; tests added in `rsvp_model`.
- REV-8: fixed. New `private.rsvp_is_expired` (the cover uses it too); `rsvp_create_links(p_items, p_now)` and `rsvp_rotate_link(..., p_now)` raise `link_expired`; `rsvp_mark_shared(p_link_id, p_now)` evaluates "works" with `p_now`. Six tests in `rsvp_lifecycle`; allowlists/types updated.
- REV-9: done. `lc_obs` now asserts for every link that `rsvp_resolve` (page) agrees with `rsvp_cover` (list), on all 54 rows.
- REV-10: renamed to `guests_id_wedding_id_key` (migration not deployed).
