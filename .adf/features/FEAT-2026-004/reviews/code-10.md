## QA-B (retry_after 901)
`private.rsvp_hit` uses `now()` (transaction start). A submit that waits on the row lock started before the transaction that set `locked_until`, so `locked_until - now()` can exceed 900 by the wait. Impact: none on security (the 20-write bound is serialised by the lock and verified) and none on the user: `public-actions.ts:45-46` drops the seconds and the form shows a fixed text; the 429 at open uses `rsvp_gate`, which only reads a lock committed before its own start, so it stays <= 900 (tested). The concurrency test accepts up to 960 (`rsvp.concurrency.test.ts:135`). Accept as is; no code change. If wanted, `least(900, ...)`, but not needed.
